# 灵息 · AuraMate

**产品技术文档 · MVP / Open Source**
*A gentle tap, not an interruption.*

* **产品名称**：灵息 (AuraMate)
* **代码库名**：`auramate`
* **说明**：名称作为正式工作名及开源仓库名；正式发布前再做域名、商标和平台名称的最终清查。

## 1. 产品定位

AuraMate 不是“更好看的番茄钟”，而是一个不打扰、不分心，但会持续照顾工作—休息节奏的**桌面伙伴**。Pomodoro 是基础机制，核心价值是让用户在保持专注的同时，得到温和、可感知的提醒，并在需要时自然地休息。

* **低打扰**：默认不抢焦点、不全屏、不强制阻断当前任务。
* **不分心**：视觉和宠物都是环境提示，不构成额外游戏任务。
* **温柔监督**：系统持续关注工作、休息和超时，但最终决定权交给用户。
* **存在感知**：只判断“人还在不在”，不监控“人具体在做什么”。
* **Local-first**：核心功能离线可用，活动状态默认本地处理。

## 2. 核心体验与交互原则

| 原则 | 设计要求 |
| --- | --- |
| **不打扰** | 提醒首先改变环境感知，其次才使用系统通知；避免抢焦点、全屏弹窗和强制中断。 |
| **不分心** | 主界面只呈现当前阶段、剩余时间和最少操作；历史/统计藏在次级页面。 |
| **看得见但不碍事** | 状态应可在 Tray/Menu Bar、角落小控件或宠物动作中被一眼感知。 |
| **提醒是建议** | 允许 +5 / +10 分钟、Snooze、Skip；不把“没休息”设计成失败。 |
| **优先观察再提醒** | 到点后先判断用户是否 Active / Away，再决定是否继续提醒。 |
| **已经休息就别催** | 若用户在提醒前后离开电脑一段时间，应把它视为可能的自然恢复期。 |

## 3. 典型交互流程

开始 Focus → 保持安静 → 到点 → 先判断 Presence → 只在需要时进行 Gentle Nudge → 用户可继续、Snooze 或休息 → Away 期间减少无意义提醒 → Returned 后自然恢复下一阶段。

| 场景 | 系统行为 | 用户感受 |
| --- | --- | --- |
| **专注中** | 仅保留轻量状态；宠物保持安静或做低频待机动作。 | 几乎感觉不到工具存在。 |
| **Focus 到点** | 先出现 ambient 提示；默认不抢焦点。 | “我知道了，但没有被打断。” |
| **用户继续工作** | 进入轻量 Overrun 状态，可 +5 / +10 分钟。 | 提醒是建议，不是强制。 |
| **用户深度心流** *(新增)* | 若多次无视提醒并持续高频输入，自动静默转入 Hyper-Focus 记录模式，暂停打扰。 | 灵感爆发时不被工具生硬打断。 |
| **用户离开** | 切换到 Away，降低或停止主动提醒；记录离开区间。 | 已经离开就不用继续被提醒。 |
| **用户回来** | 识别 Returned，根据上下文继续 Focus / Break 或提示下一步。 | 回来后自然接上。 |
| **恢复阶段** | 把喝水、走动、眼睛休息合并成一次微恢复提示。 | 一次完成一组动作，不被连续打扰。 |

## 4. Presence Awareness（存在感知）

一期只做粗粒度 Presence Awareness。目标不是记录生产力指标，而是避免在用户已经离开电脑后继续发无意义的提醒。

| 状态 | 概念判定 | 产品行为 |
| --- | --- | --- |
| **Active** | 近期存在键盘、鼠标或系统活动。 | 正常工作状态；按提醒策略工作。 |
| **Media/Meeting** *(新增)* | 识别到全屏媒体播放、麦克风或摄像头高频占用。 | 视为 Active 特殊子状态，推迟视觉提醒，防止干扰观影或会议。 |
| **Away** | 连续一段时间没有输入。 | 降低/暂停主动提醒；可作为自然休息记录。 |
| **Locked/Sleeping** | 系统锁屏、睡眠或类似状态。 | 停止主动提醒；恢复后重新评估。 |
| **Returned** | 从 Away / Locked 恢复到 Active。 | 根据上下文恢复，而不是积压通知。 |

**隐私边界**：一期不记录屏幕内容、键盘内容、网页内容、鼠标轨迹或详细应用使用历史；默认不上传 Presence 数据。

## 5. 分期方案

路线顺序已经确定：一期先把核心节奏做顺；二期优先做 AI；三期再扩展更丰富的 Companion System。

| 阶段 | 目标 | 主要能力 | 明确不做 |
| --- | --- | --- | --- |
| **一期 · MVP** | 验证“温柔提醒 + Presence”体验。 | Focus / Short Break / Long Break；Active / Away / Locked / Returned；Ambient Nudge；Snooze / +5 / +10；2–3 个可选宠物；Tray ；本地历史。 | 养成、积分、金币、签到、复杂装扮、社交、强制专注。 |
| **二期 · AI** | 让系统理解并适配个人节奏。 | 节奏建议；智能调整 Focus/Break；每日复盘；可插拔 AI Provider；优先基于本地历史生成上下文。 | 常驻聊天机器人、强依赖单一模型、把 AI 变成主要 UI。 |
| **三期 · Companion** | 增加陪伴感和表达力，不游戏化。 | 更多宠物；更丰富动作；轻量人格；更细腻的状态反馈；可扩展宠物资源机制。 | 等级、任务链、繁殖、复杂经济系统、每日维护的游戏循环。 |

## 6. 技术方案

| 层次 | 方案 |
| --- | --- |
| **桌面框架** | Rust + Tauri 2。 |
| **项目初始化** | 使用官方 `create-tauri-app` 生成基础项目；不手工预设初始目录结构。 |
| **前端** | React + TypeScript；以官方 `create-tauri-app` 的 `react-ts` 模板为准（见 `docs/adr/0001-react-ui.md`）。 |
| **核心逻辑** | Rust 管理 Timer / Session / Reminder / Presence 状态与时间计算。 |
| **存储** | SQLite；记录必要的 session、break、overrun 和 presence 时间区间。 |
| **系统权限** *(新增)* | 早期处理好 macOS Accessibility 或 Windows 低级别 Hook 的权限请求 UX；初期可降级使用 `CGEventSourceSecondsSinceLastOSXEvent` 等低权限 API 判断空闲。 |
| **桌面交互** | System Tray / Menu Bar、非抢焦点提示、透明/置顶宠物窗口、系统通知。 |
| **时间逻辑** | 以实际时间戳计算剩余时间，不依赖简单 setInterval 累减。 |
| **AI（二期）** | Provider 抽象；支持云模型、OpenAI-compatible endpoint 和本地模型。 |

## 7. 视觉与 UI 规范（初版）

**视觉关键词**：安静、柔和、留白、轻量、自然、稍微有趣。不要“游戏 UI”，不要高密度仪表盘，也不要用大量颜色制造紧迫感。

### 7.1 色彩与排版

* **主背景**：暖白 / 雾灰（如 `#F7F6F2`）；暗色模式为深灰绿，避免纯黑。
* **主文字**：深灰 `#2F3430`；**强调色**：低饱和苔绿/鼠尾草绿（如 `#8EA394`）。
* **排版密度**：时间是第一视觉层级（优先大数字）。按钮数量控制在 1 个主操作 + 1–2 个轻操作。桌面浮层采用圆角、弱阴影、轻毛玻璃。

### 7.2 动效与多屏交互

* 动效是状态变化，不是视觉奖励；优先“出现、停留、消退”，避免闪烁、震动和突然放大。
* 宠物动作以低频 idle 为主；Focus 时尽量安静。
* **多屏适配 *(新增)***：宠物窗口和角落提示默认跟随鼠标所在的“当前活动屏幕（Active Monitor）”，确保环境提示始终在用户的周边视野内。

### 7.3 关键 UI

* **主窗口**：单屏完成 Start / Pause / Resume；显示阶段、剩余时间、宠物和少量状态信息。
* **Tray / Menu Bar**：无需打开主窗口即可完成常用动作（Pause, Skip, Snooze）。
* **Pet Window**：透明、非阻塞、不抢焦点；默认停留在工作区边缘。
* **Break Card**：展示合并后的恢复建议（如“喝口水 + 站起来走走”），不连续弹窗。

## 8. 宠物策略

一期提供 2–3 个可选角色。宠物是交互语言，不是游戏角色。

* **Cat**：安静、慵懒、偶尔探头；适合默认角色。
* **Dog**：稍微积极；适合“起来走走”类提醒。
* **Sloth / Plant**：最安静；适合不喜欢被提醒的人。

*宠物资源应与代码、第三方素材和许可证分开管理。未来新增角色时，不应要求用户学习新的规则。*

## 9. 开源与隐私基线

* 第一天即按公开仓库维护：`README`, `LICENSE`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`。
* 默认 local-first；核心计时、Presence 和历史数据本地可用。
* 默认无活动遥测（Telemetry）；若未来加入，采用明确 opt-in。
* AI Provider 可插拔；API Key 优先使用 OS Keychain/系统安全存储。
* 第三方素材（动画、字体、音频）必须明确记录来源、许可证和再分发条件。

## 10. 一期验收标准

Focus 开始后，即使不打开主窗口也能知道状态；到点默认不抢焦点，结合 Presence 判断是否 Gentle Nudge；Away 与 Returned 能自然衔接；喝水、走动、眼睛休息合并成一次温和恢复提示。宠物有趣但不需要维护，不产生游戏任务；核心功能在无网络条件下仍可用，Presence 只服务于提醒逻辑，不扩展为详细行为监控。
